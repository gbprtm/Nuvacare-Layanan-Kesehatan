# B03: slot dan janji dengan pencegahan bentrok

Tanggal: 2 November 2026

## Implementasi tahap ini

- `GET /api/slot` membaca slot berdasarkan tanggal, dokter, spesialisasi, dan
  status tersedia. Hanya slot yang belum memiliki janji aktif yang ditampilkan
  sebagai tersedia.
- `POST /api/janji` hanya menerima pasien, memvalidasi body dengan Zod strict,
  mengambil dokter dari slot server, dan membuat janji dalam transaksi.
- Constraint unik `janji_slot_aktif_unique_idx` tetap menjadi pengaman database.
  Pelanggaran constraint diterjemahkan menjadi `409 SLOT_ALREADY_BOOKED`.
- `GET /api/janji` membatasi pasien pada janji miliknya; admin dapat membaca
  daftar operasional sesuai guard server.
- `PATCH /api/janji/:id` membatalkan janji dengan alasan wajib. Pasien hanya
  dapat membatalkan miliknya sendiri dan status aktif dibatasi secara atomik.
- Semua handler terautentikasi memasang ulang cookie sesi setelah aktivitas sah.

| Perintah | Hasil |
|---|---|
| `npm run typecheck` | Lulus |
| `npm run lint` | Lulus |
| `npm run test:db -- tests/integration/janji/janji.db.test.ts` | Lulus, 2/2 |

Skenario PostgreSQL membuktikan tamu ditolak, daftar slot tersedia, dua request
serentak pada slot yang sama menghasilkan tepat satu `201` dan satu `409`, pasien
hanya menerima janji miliknya, dan pembatalan dengan alasan mengubah status
menjadi `dibatalkan`.

## Sisa dan batas scope

Kontrak juga mencatat daftar dokter serta endpoint admin untuk membuat/mengubah
slot. `docs/tinjauan-backend-agen.md` BE-03 menandai konflik pemilik endpoint:
paths B03 hanya mencakup `/api/slot/**` dan `/api/janji/**`, sedangkan dokter dan
pengelolaan slot admin belum memiliki pemilik yang disetujui. B03 tetap `doing`
hingga pembagian endpoint tersebut diputuskan atau scope diperluas.
