# Bukti Tahap 2: API Auth & Halaman Login HTML

## Ringkasan
- Endpoint yang dibuat:
  - `POST /api/login`: Otentikasi email dan password, validasi error 422 bila salah, respon token Bearer dan objek user `{ id, name, email, role }`.
  - `POST /api/logout`: Menghapus personal access token aktif pengguna, respon `{ message: "Logged out" }`.
  - `GET /api/master-poli`: Mendapatkan daftar poliklinik dan dokter aktif, terlindungi `auth:sanctum`.
- Model `App\Models\PersonalAccessToken` mengikat Sanctum ke schema `klinik.personal_access_tokens`.
- Frontend aset terisolasi di `public/`:
  - `public/css/style.css`: Token CSS sesuai `DESIGN.md` (Navy `#0A2540`, Teal `#00D4B2`, Netral `#F8FAFC`, Border `#E2E8F0`, tipografi sistem, mobile-friendly).
  - `public/js/api.js`: Helper client API berbasis `fetch()` dengan manajemen Bearer token di `localStorage` dan penanganan auto-redirect status 401.
  - `public/js/auth.js`: Penanganan interaksi form masuk, validasi sisi klien, serta auto-redirect sesuai role (`admin` atau `pasien`).
  - `public/login.html`: Halaman masuk bersih berbahasa Indonesia dengan petunjuk akun demo seeder.
- Pengujian:
  - `tests/Feature/AuthApiTest.php` (5 tests passed, 53 assertions).
  - Linter: Pint passed cleanly.
