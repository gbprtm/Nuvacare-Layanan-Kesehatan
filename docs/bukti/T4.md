# Bukti Tahap 4: Janji Temu & Panel Admin

## Ringkasan
- Endpoint Pasien:
  - `GET /api/janji-temu`: Mengambil daftar janji temu pasien dengan filter `type = 'janji_baru'` dan `status = 'terjadwal'`.
  - `POST /api/janji-temu`: Membuat janji temu baru dengan status default `'terjadwal'` dan jenis `'janji_baru'`. `user_id` otomatis diambil dari token pasien yang login.
- Endpoint Admin:
  - `GET /api/admin/janji-temu`: Mengambil daftar seluruh janji temu dan kontrol pasien dengan filter status dan tipe.
  - `PATCH /api/admin/janji-temu/{id}`: Mengubah status janji temu (`terjadwal`, `selesai`, `dibatalkan`) dan mengisi catatan dokter (`doctor_notes`).
  - `POST /api/admin/jadwal-kontrol`: Membuat jadwal kontrol bagi pasien dengan jenis `'kontrol_rutin'` dan status `'terjadwal'`.
  - `POST /api/admin/poli`: Menambah data poliklinik baru.
  - `POST /api/admin/dokter`: Menambah data dokter baru pada poliklinik.
  - `GET /api/admin/pasien`: Daftar pasien untuk kemudahan pemilihan saat penetapan jadwal kontrol.
- Frontend:
  - `public/pasien/janji-temu.html`: Antarmuka booking janji temu mandiri dengan dropdown poli & dokter serta tabel janji aktif.
  - `public/admin/kelola-janji.html`: Antarmuka admin untuk mengelola status kunjungan, menambahkan catatan dokter via modal, dan form penjadwalan kontrol pasien.
  - `public/admin/master-data.html`: Antarmuka admin untuk menambah dan meninjau poliklinik serta dokter.
  - `public/js/admin.js`: Pengendali interaksi panel admin dengan otentikasi role `admin`.
