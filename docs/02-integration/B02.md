# B02: persiapan profil kesehatan pasien

Tanggal: 1 November 2026

## Keputusan pemilik

Login menggunakan email dan kata sandi. NIK dan nomor Kartu Keluarga (KK)
tidak diperlukan dan tidak dikumpulkan oleh API auth/profil. Kebijakan kontrak
ada di `docs/api-contract.md`, FR-01 dan FR-07. Kolom `nik` pada database lama
belum dihapus; dokumentasi tidak dianggap sebagai migrasi.

Keputusan ini tidak menghapus kebutuhan kondisi, alergi, dan daftar obat pada
profil kesehatan sesuai FR-01. Profil kesehatan terpisah dari kredensial login.

## Tahap 1: endpoint profil

Tahap pertama dikerjakan setelah verifikasi B01 lulus, meskipun B01 masih
menunggu commit sesuai izin pemilik. Endpoint yang tersedia:

- `GET /api/profil`: membaca profil milik pasien yang sedang masuk.
- `PUT /api/profil`: membuat atau memperbarui profil milik pasien sendiri.
- `DELETE /api/profil`: menghapus profil setelah `{ "konfirmasi": true }`.
- Semua mutasi divalidasi Zod strict.
- NIK dan KK tidak diterima sebagai field API.
- Admin dan tamu ditolak oleh guard server.
- Route profil memasang ulang cookie sesi setelah aktivitas yang sah.
- `GET /api/profil` menangkap daftar `obat` yang dilaporkan pasien.
- Tidak ada endpoint CRUD obat untuk pasien; `PUT /api/profil` menolak field obat.
  Mutasi obat disiapkan untuk alur admin/internal.

## Batas dan pekerjaan lanjutan

- B02 tidak menyediakan CRUD obat untuk pasien. Pasien hanya membaca daftar obat
  melalui `GET /api/profil`.
- Mutasi obat admin/internal bukan blocker B02. Pekerjaan itu diteruskan ke B09
  pada alur resep/obat, dengan aturan pasien tidak dapat menambah obat sendiri.
- Snapshot Fornas saat ini hanya bagian A, 64 record. Cakupan B-Z dapat ditambah
  sebagai snapshot baru tanpa mengubah kontrak profil.
- Tabel `katalog_obat_fornas`, importer, dan tabel `obat_pasien` sudah tersedia.

Acceptance B02 yang diselaraskan: kondisi dan alergi dapat roundtrip melalui
profil pasien; daftar obat terlihat melalui `GET /api/profil`; pasien lain tidak
mendapatkan data; pasien tidak dapat mengubah daftar obat melalui `PUT /api/profil`.
Dosis/frekuensi yang tampil adalah catatan, bukan rekomendasi medis.

## Scope tambahan yang diajukan

Di luar `paths` B02 (`src/app/api/profil/**`, `src/modules/profil/**`,
`tests/integration/profil/**`), perlu persetujuan untuk:

| Berkas | Alasan |
|---|---|
| `src/db/schema/pasien.ts` | Penyimpanan obat laporan pasien terpisah dari resep admin |
| `src/db/migrations/**` | Migrasi dan metadata perubahan skema |
| `vitest.db.config.ts` | Menemukan test PostgreSQL profil |
| `docs/api-contract.md`, `docs/database-schema.md` | Kontrak field dan skema mengikuti persistensi yang disetujui |

Usulan minimum: daftar nama obat laporan pasien berupa array string, disimpan
terpisah dari resep admin; nama akun hanya dibaca, tidak diubah oleh PUT profil.
Field profil lain perlu aturan required/nullable eksplisit. Usulan ini belum
menjadi keputusan persistensi atau izin menjalankan migrasi.

Menghapus kolom NIK lama bukan prasyarat mengecualikannya dari API. Jika pemilik
menghendaki penghapusan fisik, scope juga mencakup penyesuaian seed dan test yang
masih merujuk kolom tersebut, setelah seluruh rujukan ditemukan.
